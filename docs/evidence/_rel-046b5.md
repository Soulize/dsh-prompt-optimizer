# v0.4.6-beta.5 — 思考强度真正生效（含守卫与可证伪验证）

作者：啃轮胎的西狐 · 2026/09/18

## 病根

「优化 AI 思考强度」这个控件**从来没生效过**：

- 只有**内部自检路径** `streamOnce` 会发 `reasoningEffort`；**正式优化路径** `streamWithTools` 构造 `llm.stream({...})` 时**从不包含该字段**，它的两个调用点（工具循环分支、普通分支）也都没传；
- `/runs` 记的 `effort` 是 `effortForCall()`，即**配置值**而不是**实发值** —— 所以"看起来设置生效了"是错觉；
- 于是 v0.4.5 那条"off 均值 8745 / max 8300 / 未设置 2788，行为层面的强度差异尚未被证实"，其实是在**测空气**：三组发出去的东西一模一样，差异全是噪声。

## 改动

1. **接线**：`streamWithTools` 现在会带上 `reasoningEffort`；工具循环分支、普通分支与 `runToolLoop` 贯通同一条 `selection`（`runToolLoop` 新增可选的 `selection` 入参）。
2. **可审计**：`/runs` 同时给出 `effort`（配置）/ **`effortSent`（实发，null = 没发）** / `effortNote`（未发原因：`unset` / `no-llm-route` / `model-declares-no-efforts` / `not-declared-by-model` / `info-error:…` / `declared`）。
3. **守卫**：**只在该模型确实声明了该档位时才发** —— 换过模型后残留的档位不会再让正式优化直接 400。
4. **UI**：弹层提示补一句"该模型未声明所选档位时不会发送"（中英条目继续一一对应）。

## 验证

**可证伪实验**（同一请求、basic 档、各 4 次；`evidence/effort-live.json`）：

| 组 | 思考文本（4 次） | 中位 | effortSent | effortNote |
|---|---|---|---|---|
| `off` | 0 / 0 / 0 / 0 字 | **0** | `"off"` | declared |
| `max` | 3260 / 1974 / 2193 / 2274 字 | **2234** | `"max"` | declared |

**类别级差异（0 vs 2234）** —— 若字段仍未发送，两组只会有噪声级差异（历史数据正是如此）。

**守卫单测**（`evidence/verify-effort-guard.cjs`，7/7）：未设置 → 不发；无 llm 路由 → 不发；模型不声明任何档位 → 不发；**模型声明了档位但没有 `max` → 不发**（这条在本机跑不到：目录里 5 个模型都声明全部四档，所以用 stub 定死，避免成为"写了但永远没验过"的死代码）；模型声明 `max` → 发；能力查询抛错 → 不发且不炸；配置 `off` 且声明 `off` → 发。

**回归**：`delivery=chat` 三档 system 仍**逐字节不变**（15/15）；投影不变式（只动 `sequence`/`budget`）✓；i18n parity 无漏译 ✓。
