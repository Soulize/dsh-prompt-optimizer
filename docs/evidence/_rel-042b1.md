## 0.4.2-beta.1 — 策略 v4.1：覆盖优先 + 终局单次验证

### 为什么要改（底层推理，不是手感调整）
v4 把"不确定 → 探针"做成主线，实际表现为**反复验证、边做边验**，把预算花在了检测上。但底层事实是：

1. **出错几乎全因"提示词没考虑到"**，而**再多的检查也找不出一个从没被写进去的要求**——检测无法弥补遗漏；
2. 每次检查在 PTC 里都要占**程序篇幅 + 执行时间 + 下一轮上下文**，代价很高（实测：要求"逐步验证并贴证据"的旧策略
   把执行端程序撑爆，10/24 格被判预算截断而白扔）；
3. 唯一与"用户将来满不满意"**同分布**的观测，是**完成后在真实媒介里对成品看一次**——其余都是代理的代理。

结论：**把预算的绝大部分给"覆盖"，验证降级为一次终局观测。**

### 新策略的形态
五节结构：**目标** → **完成时应当是什么样**（＝验收清单，覆盖度的全部载体，逐条写明"什么情况算没做到"）→
**要做的事**（纯动作，具体到文件/位置/字段；**不挂验证、不挂"预期"**）→ **隐含要求**（只加检查与约束，不加工作量）→
**交付物与最后一次观测**（做完后对成品看一次，逐条回执 + 未验证清单）。

验证只有三条纪律：① 不边做边验（中途最多"偶尔看一眼"，不是门、不产生分支）；② 只在真实媒介里、对成品、看一次；
③ 那一次必须能失败（永远为真的检查禁止）。修复类任务＝动手前一张基线 + 修完一张对比，**两次截图够了**。
探针能省就省：优先"构造上稳健"（例如直接本地内联资源，而不是先探 CDN 通不通），确需时才一句话写完。

### 活实例实测（坦克履带那句 20 字请求）
- 产出 **2164 字符**（v4 为 4588 —— 减半，预算从检测转向覆盖）；
- 逐步验证痕迹归零：`预期：`=0、`探针清单`=0、`观测点与基线`=0；
- 步骤为纯动作，其中第 3 步给出**病因分类**（资源 404 / 模型节点可见性 / 材质 opacity·alphaTest·色彩空间·背面剔除 /
  UV 与图集 / 遮挡与深度 / 加载时序被静默 catch / canvas 与 DOM 层叠）——这是覆盖；
- 中途只保留"重新加载真实画面**看一眼**（顺带一看，**不作为关卡**）"，末尾一次终局观测 + 逐条回执。

工程：旧策略（`v4` / `stepwise` / `v011-ptc` / `v03x`）全部保留可作 A/B；零依赖不变；UI 与功能未改。
