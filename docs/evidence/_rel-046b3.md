## 1. 修复：高级/极端档看不到思考过程

三处断点（每处都有代码依据）：

| 断点 | 位置 | 症状 |
|---|---|---|
| 工具循环调 `streamWithTools` **漏传第 9 个参数 `onDelta`** | `lib/index.js:1516` | 思考增量根本不外发 |
| 循环只回传 `reasoningChars` **计数**，原文丢弃 | `lib/index.js:1546` | 只有长度、没有内容 |
| `executeLiveRun` 工具分支把 `reasoning` **硬编码为空串** | `lib/index.js:2065` | 回传链路终端被清空 |

基础档不派工具、走流式直通路径，所以一直正常——这正是"只有高级/极端看不到"的原因。

修法：把思考接回**与不派工具时同一条**透传通道（`opts.onDelta` 透传 + 回传 `reasoning` 原文 + 工具分支赋值）。工具分支只转发 `reasoning-delta` / `usage`；**正文不走这里**，因为工具循环是多轮的、正文以最后一轮为准，仍由原来那一次 `publishRun` 定稿，不重复推送。

**三档定义未动**：`V6_TIERS` 的 `grounding / decompose / enrich` 与温度一字未改。

实测（同一请求、同一模型、同一 effort）：思考文本字数 基础 **3333**（未受影响）、高级 **0 → 2817**、极端 **0 → 7396**；浏览器内实跑极端档，「思考」折叠栏摘要 = **`— tok · 6497 字`**。

## 2. 问号面板（使用帮助）文案与实际行为对齐

原先那一节写的是 v0.2.1 / v5 时代的规则（"实质优先 / 流程长度 / 硬约束 / 防过度"），而 v6 明确"不写流程仪式与通用教学"——**两者正好相反**。现按三档定义重写：

- **档位**：三档各补到什么程度，并注明**三档的思考过程都显示在「思考」栏**；
- **只读权限**：默认开启、高级/极端档能读什么（`read/glob/grep`，限定项目根内、不写盘、不执行命令）、关掉会怎样；
- **优化器会做什么**：收件人 / 语言层 / 保真 / 歧义 / 产出即命令——与 `V6_CORE` 五段一一对应；
- **上下文**：回合＝最近 0~10 回合**双方全文**；超限按六级分级压缩并写明压缩了什么。

同时修掉两条过时描述：回合模式"只保留你的原话"、"上限 回合 1.2 万 / 全文 6 万字符、按整回合丢弃"。

中英**逐条对齐**：面板在中英两种语言下**各 7 节 / 各 24 行**；`i18n-demo` 自检断言同步改为校验新条目，中英各跑一次 `pass: true`；`verify-i18n-parity.cjs` 审计 **0 漏译**。
