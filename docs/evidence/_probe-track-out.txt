目标：坦克的履带在正常运行/渲染时可见且表现正常——能看出履带的轮廓与材质，在移动、转向、静止状态下随车体正确显示，与车体及负重轮连接处无缝隙、无穿模，且坦克其余部件的外观与行为不发生任何变化。

步骤：

1. 先确定这个项目的运行方式和坦克出现的位置：读项目根目录的说明文件与 package.json / 工程文件，找到启动命令；用该命令把项目跑起来，让坦克出现在画面中（默认场景 / 关卡 / 页面 / 预览视图）。｜预期：能记录下确切的启动命令与坦克出现的具体位置（场景文件名、路由、或坐标）。若命令跑不起来、或坦克不在默认位置出现，属于此步失败：此时记录报错原文和失败的确切位置，并改为通过项目里已有的场景/关卡/预览入口逐个打开，直到画面中确实出现坦克为止。

2. 把"履带"在项目里的实现全部定位出来：全文搜索 track、tread、Track、履带、wheel、wheelMesh 等关键词，同时打开坦克的模型文件与预制体/场景节点（.fbx / .gltf / .glb / .obj / .prefab / 场景文件），逐层展开坦克的子节点层级。｜预期：得到一份具体清单——履带对应的网格节点路径、它引用的材质与贴图、以及控制它显隐/渲染/动画的代码（文件路径 + 行号或节点路径）。清单里必须能明确回答"履带是哪个节点、哪个材质、哪段代码在管它的显示"。若关键词搜索零命中，必须靠节点层级把履带子节点找出来并给出确切路径；找不到就是本步失败，不允许跳过。
　　（采用解读：把"显示不出来"按最保守的方式理解为"履带在正常运行中完全不可见或明显异常"，优先按"完全不可见"处理。若实际表现是错位、穿模、材质丢失等其他形态，走同一套定位—修复—复验流程，不额外添加用户没要求的新功能或美化。）

3. 直接观测，把问题复现出来并定性：按第 1 步的方式运行，让坦克出现在画面中，对全车截图，再对履带所在区域单独放大截图；至少换两个视角（正侧面、斜前方）与两个距离（常规、拉近）各截一次。同时记录履带此刻的实际表现属于哪一类：完全不可见 / 全黑 / 全透明 / 材质丢失（白块或紫块）/ 位置错位 / 被车体或地面遮住 / 只显示一侧。｜预期：截图里问题能被一眼指认，且能归入上面某一类具体表现，而不是"看起来怪怪的"。若截图里履带其实正常，说明问题只在特定条件下出现——换成播放移动动画、转向、切换画质档位、换关卡后再截，直到在某个条件下复现并截图为止。

4. 针对第 3 步观测到的具体表现修复，只改履带相关的部分：按现象对应的原因动手（可见性/图层开关、材质或贴图引用丢失、骨骼或蒙皮未绑定、贴图路径与导入设置、节点缩放为 0、被视锥剔除或排序遮挡等），不要顺手重构、不要动坦克其他部件与无关代码。｜预期：每一处改动都能对应到第 3 步观测到的某个现象，并能说清"为什么这会导致我看到的现象"；改动文件全部落在第 2 步列出的履带相关位置上。若项目需要重新导入模型或重新烘焙，按项目正常流程执行，不引入新的外部资源或下载。

5. 修完再直接观测一次，做前后对比：重启并重新运行，在与第 3 步完全相同的视角、距离、条件下重新截图，与修复前截图并列；同时让坦克移动并转向（若存在履带转动/滚动动画），连拍多帧或录一段，覆盖静止、移动、转向三种状态。｜预期：新截图里履带可见、材质颜色正常、随车体移动与转向一起动作，与车体/负重轮连接处无缝隙、无穿模、无悬空；新旧截图并列后差异明显到无需解释即可看出。

验收清单：
- 默认视角下履带可见，截图里能看出履带轮廓与材质，不是空白或纯色块。
- 正侧面、斜前方两个视角下履带都可见。
- 履带在坦克移动、转向、静止三种状态下都正常显示，移动/转向时履带随车体一起动作，不是静止贴片。
- 履带与车体、负重轮的连接处无缝隙、无穿模、无悬空。
- 坦克其余部件（车体、炮塔、炮管、负重轮等）的外观与行为与修复前一致，附前后对比截图。
- 运行日志/控制台中不出现与履带、材质、模型加载相关的新报错（附日志片段或进程退出码）。
- 版本差异里只包含履带相关的文件改动，没有无关文件的改动。
- 修复前与修复后的截图都保留，路径写进交付说明。

隐含要求：
- 不许改动坦克的尺寸、比例、配色、贴图内容，不许改动履带以外的任何部件。
- 不许用临时手段掩盖问题（强制放大履带、关闭视锥剔除导致穿模、写死显隐开关等），要修的是根因；若确实必须保留某个兼容性开关，需说明原因与影响范围。
- 边界视角要正常：相机贴近、拉远、俯视时履带都得可见且不变形穿模。
- 画质档位/LOD 切换后履带同样可见（项目若有多档画质或 LOD）。
- 不引入新的外部资源、依赖或下载。
- 项目若有开发模式与打包/发布模式之分，至少在使用的运行模式下验证；若两种模式都常用，两种都要看一眼。

交付物：
- 修改后的源码/资源文件，逐个列出路径。
- 修复前与修复后的截图：全车图 + 履带区域放大图，至少覆盖正侧面、斜前方两个视角，以及移动/转向状态。
- 一份简短说明：根因是什么、改了哪些点、怎么验证的。
- 运行命令与环境信息（启动命令、引擎/依赖版本）。
