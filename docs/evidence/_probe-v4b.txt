一、目标与判据  
目标：在项目真实运行媒介中，让实际复现“履带显示不出来”的那辆坦克的履带从不可见变为可见，且刷新后仍可见、控制台无新增履带相关错误、坦克其他部件不变。  
成功长什么样：在项目原生运行方式里打开含该坦克的页面/窗口/场景，同一 URL/场景、同一视口分辨率、同一相机角度下截图，履带区域出现可辨认的履带几何/材质/纹理；刷新后仍可见；控制台无履带资源 404、材质编译错误或相关异常；after 截图与 baseline 截图肉眼可见差异。  
失败长什么样：履带仍缺失、透明、黑块、只显示线框或只在某些角度缺失；控制台有履带模型/贴图 404 或 shader 报错；after 与 baseline 截图无肉眼可见差异；修履带导致车身、炮塔、阴影、动画或页面其他功能异常。  
主观词翻译：  
- “显示不出来” → 真实运行媒介的同一视角截图中，履带区域没有可辨认的履带几何/纹理/颜色，或与背景无法区分；可能伴随 console 资源 404 或材质编译错误。  
- “修一下” → 修复后同一视角截图肉眼可见履带；刷新后仍可见；无新增履带相关错误；坦克其他部件与基线一致。  
- “坦克” → 项目/页面/场景中实际复现履带缺失的那辆坦克对象；通过搜索与运行确认，不靠猜测。  
- “帮我看看” → 先定位再改，只改履带显示相关处，不改无关文件。  
采用解读：若项目里有多辆坦克或多个履带对象，本次只修能复现“履带不显示”的那个；若多个坦克共用同一履带资产，则一并生效，不逐个重做。若无法唯一确定，选最近修改且能复现缺失的页面/对象，并在回执写明。

二、观测点与基线  
媒介与打开方式：先读项目内 `README*`、`package.json`、`vite.config.*`、`webpack.config.*`、`index.html`、Unity/Unreal 项目文件或启动说明，确定项目原生启动命令并运行。若有 `package.json` 且 scripts 含 dev，则用对应包管理器跑 dev；若是 Unity/UE，打开对应场景。最终以真实浏览器窗口或真实渲染窗口截图为准；无头浏览器可辅助定位，但不能单独宣告完成。  
基线：动手前先记录“现在长什么样”：  
- 截图 `baseline_track_missing.png`，覆盖整个视口，保留 URL/场景名、分辨率、相机角度、时间。  
- 复制 console 原始报错文本。  
- 记录 Network 中坦克模型、履带模型、履带贴图的请求状态（200/404/失败）。  
- 记录场景树/层级中坦克根节点及子节点列表：名称、visible、scale、材质、几何类型。  
- 若项目无法启动，基线就是启动命令、完整报错、退出码。

三、步骤（风险优先）  
1. 启动真实媒介。动作：按项目实际启动方式运行，打开含坦克的页面/窗口/场景。预期：能看到坦克或至少场景内容，并能截图。若不符：记录命令与报错原文；换端口、清构建缓存、换浏览器/无头模式再试；仍失败则只修阻塞启动的最小错误；若超出最小范围，标为未验证并继续用已有构建产物定位。  
2. 确认指代。动作：全局搜索 `坦克|tank|履带|track|Track|tracks`，列出文件、路由、场景、对象名；运行候选页面，找到履带缺失的那辆坦克。预期：确认唯一对象路径，如 `Tank/Tracks/L`、`scene.getObjectByName('track_L')`。若不符：多个候选时，采用解读：以最近修改且能复现“履带不显示”的对象为准，记录路径；仍无法确认则先修能复现的那个，并在回执写明。  
3. 记录基线。动作：按第二节保存截图、console、Network、场景树。预期：得到可对比的原始证据。若不符：补齐证据后再改代码。  
4. 检查履带节点是否存在。动作：临时输出场景树/层级中坦克所有子节点，筛选 `track/履带`。预期：存在履带 mesh/skinnedMesh/part，且 visible=true、scale 非 0。若不符：节点不存在 → 检查模型加载后是否被改名、合并或删除；visible=false 或 scale=0 → 记录并修对应属性；材质透明或贴图丢失 → 进入探针 5。  
5. 材质/贴图探针。动作：临时把履带材质换成不透明纯色（如红色）或 `wireframe=true`，在真实媒介截图。预期：履带区域出现红色或线框。若不符：仍不可见 → 病灶在几何/变换/层级/遮挡/裁剪；若出现 → 病灶在材质/贴图/透明通道/UV，按结果修。  
6. 变换/遮挡/裁剪探针。动作：打印履带 mesh 的 position/rotation/scale/visible/frustumCulled/boundingSphere/renderOrder；临时关闭其他部件或调整 depthTest/renderOrder 对比。预期：数值正常、不被其他部件遮挡、不在相机裁剪外。若不符：对应修 scale/position/visible/frustumCulled/renderOrder/depthTest；仍不显示则检查相机 layer 与模型 layer。  
7. 动画/骨骼探针。动作：暂停或禁用履带动画/骨骼驱动，再看静态是否显示。预期：静态显示。若不符：动画驱动导致隐藏或 NaN 变换 → 修动画/骨骼绑定；静态仍不显示 → 回探针 5、6。  
8. 修复。动作：只改与履带显示直接相关的文件/属性。预期：真实媒介里履带可见。若不符：保留尝试记录，回到对应探针，不做无关重构。  
9. 复观测与回归。动作：用同一启动命令、同一 URL/场景、同一视口、同一相机角度重新截图 `after_track_visible.png`；刷新再截一张；复查 console、Network、坦克其他部件。预期：after 与 baseline 在履带区域肉眼可见差异；无新增履带相关 404/报错；车身、炮塔、阴影、动画与基线一致。若不符：按差异定位继续修；仍 fail 的写进回执。  
10. 清理临时调试。动作：删除临时 console、红色材质、wireframe、诊断代码。预期：交付文件中无临时调试痕迹。若不符：删除后再交付。单测/静态检查只能辅助定位，最终 pass 必须来自真实媒介截图。

四、探针清单  
1. 问题：项目能否以原生方式启动？｜最小实验：按 README/package.json 的实际脚本运行，打开页面/场景｜失败：命令报错、页面空白、无坦克｜失败改走：换端口、清缓存、换浏览器/无头；仍失败则修阻塞启动的最小错误，并记录命令与报错。  
2. 问题：用户指哪辆坦克、哪条履带？｜最小实验：搜索 `坦克|tank|履带|track`，运行候选页面，截图对比｜失败：多个候选均可能，无法唯一确认｜失败改走：采用最近修改且能复现缺失的对象，记录路径，回执写明采用解读。  
3. 问题：履带资源是否被加载？｜最小实验：Network 面板看履带模型/贴图请求｜失败：404、跨域、路径大小写错误｜失败改走：修资源引用路径/大小写/导入设置，不换美术风格。  
4. 问题：履带节点是否存在于场景？｜最小实验：临时打印含 `track/履带` 的场景节点｜失败：节点不存在，或被合并/改名/删除｜失败改走：修加载逻辑或命名映射，找到实际履带节点。  
5. 问题：履带材质/贴图是否有效？｜最小实验：临时换成纯色不透明材质或 wireframe｜失败：仍不可见｜失败改走：若纯色可见，修材质/贴图/透明/UV；若纯色仍不可见，转几何/变换/遮挡探针。  
6. 问题：履带变换是否有效？｜最小实验：打印 position/rotation/scale/visible/frustumCulled/boundingSphere｜失败：scale=0、visible=false、位置异常、包围球无效｜失败改走：修对应属性，只改履带相关值。  
7. 问题：是否被遮挡或裁剪？｜最小实验：临时隐藏车身/炮塔，或调 depthTest/renderOrder/layer 对比｜失败：仍不显示或只在特定角度缺失｜失败改走：修遮挡、renderOrder、depthTest、layer、frustumCulled。  
8. 问题：是否由动画/骨骼控制？｜最小实验：暂停履带动画，看静态是否显示｜失败：静态仍不显示｜失败改走：若静态显示，修动画/骨骼；若仍不显示，回材质/变换探针。  
9. 问题：是否刷新后复现？｜最小实验：刷新页面/重开场景，同角度截图｜失败：刷新后又不显示｜失败改走：查持久化状态、异步加载、缓存、初始化顺序。  
10. 问题：修复是否破坏其他部件？｜最小实验：同视角对比 after 与 baseline，检查车身/炮塔/阴影/动画｜失败：其他部件异常或 console 新增错误｜失败改走：回滚无关改动，只保留履带修复。

五、隐含要求  
- 只修履带显示，不新增功能、不重构、不换坦克、不重绘美术、不做履带物理/动画/性能优化。  
- 只改与履带显示直接相关的文件；不改无关业务代码、资源、构建配置、依赖版本、锁文件，除非证明是阻塞观察或履带显示的直接原因；若必须改，最小化并在回执说明。  
- 错误路径要覆盖：资源 404、路径大小写、跨域、贴图 alpha、双面材质、frustumCulled、layer mask、shader 编译错误、骨骼 NaN、scale=0、父级 visible=false。  
- 边界：至少验证原始视角 + 刷新；若条件允许再换一个相机角度或分辨率，但不作为阻断。  
- 回归约束：坦克其他部件、动画、阴影、页面其他功能与基线一致；不引入新的 console 错误。  
- 兼容性：使用项目已有浏览器/引擎版本，不升级依赖；本次不涉及语言/主题改动，若项目有暗色主题/多语言，不改动它们。  
- 采用解读：本次不做履带物理、动画重做、美术重绘、性能优化；只保证原本应显示的履带在真实媒介中可见且不破坏其他显示。

六、交付物与回执  
产物：修复后的相关文件路径 + 简短改动说明；临时诊断代码已删除。  
证据：必须是原始可见证据，来自真实媒介：`baseline_track_missing.png`、`after_track_visible.png`、刷新后 `after_refresh.png`；console 原始文本片段；Network 中履带模型/贴图请求状态；如适用，修前修后场景树/节点属性输出。  
回执：逐条对照“目标与判据”写 pass/fail；fail 的写清差在哪（例如：履带可见但刷新后消失；控制台仍有 404；车身变暗等）。  
未验证清单：哪些项没能在真实媒介里确认过；没有就写“无”。若真实媒介无法启动，对应判据必须标 fail，并列出试过的命令与报错原文。
