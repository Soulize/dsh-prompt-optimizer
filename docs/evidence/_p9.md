## 九、v0.3.0-beta.1：复杂任务能力包（细节逐项过关，2026/09/15）

**问题（真实使用反馈）**：在较复杂项目里（一次性搭大场景、做精细可驾驶的 3D 坦克模型）会在**细节上出过分的问题** ——
法向量反了导致"该看见的面看不见、不该看见的面看得见"、各类操控 bug、交互方式不人性化；同时既要顾全大局，又不能牺牲模型自身的能力表现。

**改法**：新增共享部件 `COMPLEX_RULES`，注入**高级/极端**档（普通档不注入，避免简单任务被撑长）：

1. 触发信号（命中任一）：多部件/多模块一起成型；3D 与几何；交互与操控；数据迁移或持久化；并发或重复触发；性能/资源预算；用户要求"一次性做好/完整/精细/能直接跑"。
2. 命中后命令必须包含六项：① 现象量化（**至少两条发现手段**：数值审计 + 视觉对照）② 分域失效模式清单（逐条变成可检查要求）③ 全局验收场景 ④ 不得降级清单（逐条列出不得被砍的能力）⑤ 影响面排序 + **改动范围边界**与**回退方式** + 本轮不做项与停手条件 ⑥ **判定标准与证据形式**（没有证据不算完成）。
3. 新增"**细节缺陷自检**"：交命令前逐条对照（法线/朝向/可见面、坐标与单位、碰撞与网格、输入映射与反馈、可恢复与可配置、幂等与回滚、并发去重与锁顺序、边界数据、性能预算与画质）。
4. 明确"**细节要求不得变成流程开销**"：是否建 goal/todo/分阶段仍只由 `PROCESS_RULES` 决定；不得写与本题无关的模板段落。

**规模**：普通档不变（1405 字符）；高级 2424 → **4450**；极端 2422 → **4448**（+83%）。

**测量（新测试集 `lab-cx`，8 题 × 6 要点 × 4 档 = 满分 144；每题 18）**

| 条件 | 得分 | 满分 144 换算 | 达标线 |
|---|---|---|---|
| 无优化（对照） | 6/288 | 3 | 未达标 |
| 发布版 0.2.2-beta.1（极端档） | 201/288 = 69.8% | 101 | 及格线（60%） |
| **v0.3（极端档）** | **265/288 = 92.0%** | **132** | **目标线（83%）** |

- 配对（两次采样均值）：**胜 7 / 负 0 / 平 1**。逐题 Δ：C1 场景 +11.5、C2 坦克 +4.5、C3 法向量 +3.5、C4 交互 +4.0、C5 重构 +4.5、C6 数据 0（双方满分）、C7 竞态 +2.5、C8 性能 +1.5。
- 噪声：同格重复采样平均极差 0.75 分/18（最大 5）。
- 时间：48 格（含 2 次重复）并发 4 共 **230 秒**；简单回归 12 格 **74 秒**。判分为确定性匹配，**不额外消耗 LLM 调用**。
- **简单任务回归**：4 道原题（数学/物理/工程）复杂包泄漏 0/4、长度比 1.11×、流程索取不比发布版重 → PASS。

**两次走过的弯路（如实记录）**

1. 判分器最初只认单一措辞（如"不得降级"），优化器换成"不得为了省事被砍掉"就被误判为没做到 → 加入**概念级同义扩展**后，同一批命令的分数从 80.6% → 84.0%（判分更公平，不是提示词变强）。
2. 一度加入"**规模闸门**"（小任务不展开完整六项）以避免撑长简单命令 → 复杂题**反而掉到 81.9%**（C5 重构 −5 分），说明"按规模裁剪检查"会削掉真正需要的细节要求；改为"细节逐项过关 + 细节要求不得变成流程开销"后回到 **92.0%**，同时简单任务仍然 0 泄漏。**结论：细节要按域全覆盖，流程开销才按规模裁剪。**

**复现**

```bash
node evidence/lab-cx.cjs                      # 生成 8 题 + 0~3 级评分卡（含同义扩展）
node evidence/lab-cx-variants.cjs             # 生成条件：raw / 发布版 / v0.3（取自提示词快照）
node evidence/prompt-snapshot.cjs lib/index.js v03   # 从源码真实组装出的 system 快照
node evidence/lab-simple.cjs                  # 简单任务回归规格
# 执行（宿主内测量台，staging 工具 cxlab；args: {specPath, variants, rep, concurrency, outPath}）
node evidence/cx-grade.cjs evidence/lab-cx.json evidence/cx-results.json   # 确定性判分
node evidence/cx-stats.cjs                    # 配对 / 噪声 / 长度
node evidence/cx-simple-check.cjs             # 简单任务回归检查
```
