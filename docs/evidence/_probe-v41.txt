**任务：修复"坦克的履带在画面里显示不出来"**

**一、目标**
让项目里坦克的履带在真实运行画面中恢复可见，并且位置、比例、贴图都正确；除此之外不改变任何其它可见表现。

**二、完成时应当是什么样（验收清单）**
用项目原有的运行方式启动，进到能看到坦克的画面，肉眼在画面里能看到履带。以下任一条不满足即算没做到：

1. 左右两条履带都在（只出现一条 = 没做到）；
2. 履带贴合车体两侧下方，不悬空、不穿进车体、不跑到车体中部或地面之外；
3. 履带尺寸与车体成比例，没有被拉成覆盖整屏，也没有缩成一条线或一个点；
4. 履带不是全透明、不是纯黑、不是纯白无纹理的方块（出现这三种，说明是没加载或参数错，= 没做到）；
5. 履带表面能看到原本该有的花纹／纹理细节；
6. 履带动画：如果项目原本履带会滚动／转动，运行中它在持续动；原本没有这个动画的，本条记 N/A，不算没做到；
7. 改动后没有新增错误：控制台无新增报错，网络面板里履带相关资源不再是 404／加载失败；
8. 回归：车体、炮塔、背景、UI、其它模型的位置／颜色／可见性与修复前完全一致（对比基线截图），任何一处发生变化 = 没做到；
9. 履带不能是"被换成别的东西"才看得见：用临时几何体、纯色块、别的贴图顶替的，算没做到。

**三、要做的事**

1. 定位：在项目里搜 坦克/tank/履带/track/tread/caterpillar/wheel 等关键词，确认履带属于下面哪一类，并写下结论（文件路径 + 行号或节点名 + 类型）：
   - 3D 模型（.glb/.gltf/.fbx/.obj）里的一个网格／节点；
   - 一张贴图或雪碧图里的一块区域；
   - canvas／绘图代码画出来的；
   - CSS／DOM 元素或图片；
   - 序列帧动画的一帧。
2. 复现并留证：按项目原有的运行方式启动，走到能看到坦克的画面，确认履带确实不可见，**先截一张基线截图**（记下视角与窗口尺寸），同时把控制台报错原文、失败请求的 URL 原文抄下来。这是修复后对比用的唯一基线。
3. 按定位到的类型修复（命中哪个改哪个）：
   - 资源 404／路径错：修正路径大小写、相对路径、打包后静态资源位置；
   - 模型节点：mesh 的 visible、scale、position，或被父节点隐藏；
   - 材质：material 为空、opacity 为 0、transparent/alphaTest 把贴图整块裁掉、map 没赋值、贴图色彩空间导致全黑、背面剔除导致只看到背面；
   - UV／图集：UV 落在贴图透明区，或雪碧图帧偏移算错；
   - 遮挡与深度：renderOrder、depthTest/depthWrite 导致被车体盖住，或 z-fighting；
   - 加载时序：贴图／模型没加载完就渲染，且失败被静默 catch —— 补上加载失败日志，并在加载完成后触发重绘；
   - canvas／DOM：绘制顺序把履带盖住、元素 display／z-index／宽高为 0、颜色与背景同色。
4. 改的过程中直接重新加载真实画面看一眼履带是否出现（顺带一看，不作为关卡）。
5. 修好后把临时加的诊断代码和调试输出全部删掉，只留修复本身。

**四、隐含要求（只约束，不加功能）**
- 只动与履带显示相关的文件；不重构、不改构建配置、不动依赖版本、不改无关文件的格式。
- 不许用"注释掉履带代码"或"把履带换成别的可见物"的方式让问题消失。
- 采用解读：如果排查后发现履带资源文件在项目里根本不物理存在（不是加载失败），不许自己造替代品顶上；只把结论写清楚（缺哪个文件、应在哪个路径、格式要求），该条按 fail 报。
- 不许顺手"修"控制台里原本就存在的无关报错。
- 兼容性：在项目原有的运行方式下确认；若项目有打包产物，开发模式与打包产物都要能显示，某一项无法验证就如实写进"未验证"。
- 若项目是响应式的，改变窗口尺寸后履带仍可见。
- 若履带原本只在特定视角／特定帧出现（例如只有侧面才看得到），保持原行为，不算 fail。

**探针（只在需要时用一次）**：定位到履带属于 3D 模型节点、却看不出错在哪时——把该模型文件单独丢进模型查看器或最小 three.js 页面加载一次：单独加载也不显示履带 → 是模型文件本身的问题（改模型或换文件）；单独加载正常 → 是场景／材质／渲染设置的问题（回项目里查）。

**五、交付物与最后一次观测**
- 产物：修改后的项目文件；回执里列出改动的文件路径与每处改了什么，以及定位结论（履带属于哪一类、根因是什么）。
- 最后一次观测：全部改完后，用原运行方式启动，走到同一视角、同一窗口尺寸，截一张成品截图（与基线截图同一观测点对比），并同时留下控制台与网络面板的原始输出。这一张图加控制台输出要能同时回答第二节的每一条。
- 回执：逐条对照第二节写 pass／fail，fail 的写清差在哪（哪条履带、什么位置、什么现象）；没能在真实运行画面里确认的，如实写进"未验证"，不要用"应该没问题"下结论。
