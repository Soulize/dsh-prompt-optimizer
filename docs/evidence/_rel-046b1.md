## 0.4.6-beta.1 — 三步改造完成（只读查证 / 观察者上下文 / 预算与压缩）

### 1. 只读查证（工具路径）—— 修通并验证
- **根因**：`relayMessage()` 返回的是**消息数组**（非工具路径当 `messages` 用），而 `runToolLoop` 的 `userText` 需要**字符串**，
  于是数组被塞成 `content:[{type:'text', text:<对象>}]` → provider 报 `messages[0].content: invalid type: sequence, expected a string`。
  宿主六种形态复刻均成功、只有插件失败，正是因为这个接线错误（不是协议问题）。
- **修复**：工具分支先把 relay 消息展平成纯文本再交给工具循环。
- **验证**（同一请求 ON/OFF 对照）：ON = **10 次真实工具调用**，产出含**真实事实**（"只有顶层目录 `attachments/`，其下 `attachments/v1/objects/`，按哈希前 2 位分桶"）；
  OFF = 0 次调用、泛化建议。另一例中它读了 5 次后**如实说明**"我可见的目录里没有 package.json，需要你在真实仓库里定位"——**读了就报实情，没编造**。
- 协议事实（备查）：带 tools 时 `content` 必须是内容块数组；工具结果必须放在紧随 assistant 的 **user** 消息里（`role:'tool'` 会被拒）；
  本模型 `systemPromptUpdate='in-history'`。

### 2. 上下文观察者视角 —— 走投影，不走事件重放
- **数据源**：会话对象暴露的 **`derived`**（会话 AI 真正看到的投影消息，实测 1418 条），不再重放事件。
- **注入方式**：`buildSystem(tier, { observerBlock })` —— 作为**结构参数进入 system**，不再塞进用户消息。
- **模式**：`turns` = 最近 N 回合**双方全文**；`full` = 整个投影；`off` = 不注入。
- **验证**（三模式对照）：turns `{chars:24672, rows:65}` / full `{chars:35232, rows:120}` / off `{chars:0, rows:0}`；
  前两者产出**引用真实历史**（"第 1 步只读工具路径已完成，从第 2 步接着做"），off 组零命中且明说"无法定位就说明缺少上下文，不要猜测"。

### 3. 溢出与压缩 —— 预算 + 分级压缩 + 声明
- **预算**：默认 12000 字符（`DSH_PO_OBSERVER_BUDGET` 可覆盖）。
- **分级**：① 未压缩 → ② 最近 4 回合 + 助手截断 600 字 → ③ 最近 2 回合 + 助手截断 200 字 → ④ 仅用户原文 → ⑤ 逐条丢弃 → ⑥ 整体省略（每一级都写进注入文本）。
- **验证**：turns 24,672 → **2,860** 字符、full 35,232 → **2,855** 字符，均 ≤ 预算；注入文本声明 **"仅保留最近 4 个回合、助手截断 600 字"**；
  压缩后产出仍命中历史话题（信号没被压没）。

### 硬约束遵守情况
- 只读开关**默认关闭**；工具路径失败**降级回正常路径**（实测 ON 异常时仍产出 4000 字，绝不给空结果）；
  观察者渲染任何异常都返回空串（保持原行为）。
