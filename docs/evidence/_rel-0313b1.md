## 0.3.13-beta.1

### 修复：settings 命名空间自愈注册

**现象**（重启后实测）：`/prompt-optimizer/api/state` 的 `settings` 从 `error: TypeError: schema is not a function`
（0.3.11 已修）变成了 **`no-settings-service`** —— 插件初始化时没拿到 settings 服务，命名空间未注册、设置镜像未启用。

**诊断**（宿主探针实测）：此刻 `ctx.get('settings')` **可用**（`register` 是函数），且 `describe()` 的命名空间清单里
没有 `prompt-optimizer`。即 **settings 服务晚于本插件挂载**，而 `initSettingsNamespace(ctx)` 只在 apply 时执行一次
→ 一次性查询永久错过。

**修法**：在既有的 1.2s 看门狗里加自愈重试 —— 只要状态仍是 `no-settings-service` 就再试一次注册（幂等，成功即停）。

### 说明
- 优化策略与提示词**逐字节未变**（basic/advanced/336 = 1273/1627/1736，与 0.3.10 一致）；UI/功能不受影响。
- 校验：`node --check` 通过；`lib/index.js` 123347 bytes、sha256 前缀 `fa4a6dd58415a8ba`；`lib/client.js` 未改动。
- **该修复需再次重启才会在活实例生效**（自愈逻辑要随新代码进入进程）；重启后应看到 `settings: registered`。
