# v0.7.9 单轮独立顾问实施计划

## 目标
沿用优化 AI 的 provider/model/reasoningEffort，注册 consult_task 工具。只处理当前用户请求内部的失败诊断和证据型成果复核，不实现跨轮记忆、自动返工或发布。

## 工作流程
1. 工作模型取得原始验证结果并自验。
2. 首次准备宣称交付完成时调用 review_result；重复失败但没有信息增量时调用 diagnose_failure。
3. 顾问独立判断，不预读主模型的通过结论；返回证据、缺口、下一步和停止条件。
4. 工作模型针对具体分歧补证据或修复。用户指出偏差后重审相关部分；日常小测试不重复咨询。

## 实施
- advisor.js：本轮会话快照、证据编号、有限成果文件读取、顾问系统提示词、结构化输出校验、可取消的有界调用、注册工具。
- index.js：复用设置与模型路由、注册及卸载生命周期、顾问元数据台账。
- 两份 package.json 设为 0.7.9；新增针对性单测及使用说明。

## 输入与权限
- 自动读取 session.snapshotEvents，从最近一条真人 user/message 开始；不拿插件注入当用户要求。
- 标注原始用户文本和工具证据；review_result 不提供 assistant 正文，不提供先前顾问报告。
- 工作模型仅提供问题、假设（诊断模式）和成果相对路径，不负责挑选全部证据。
- 复用项目根内 read/glob/grep/虚拟只读 run；不提供 shell、写文件、网络、递归咨询。遵守用户的文件读取限制，不自行扩大范围。
- 无法获得本轮原话则拒绝；证据截断和图片未解析均显式标注。

## 输出与约束
JSON 包含 verdict、summary、findings、checks、nextStep、stopCondition。每条事实引用可核证据编号，验收状态 satisfied/failed/unverified。缺证据不得通过，顾问建议不是用户授权；不能凭评分或多数票结案。

## 调用成本
每会话同一时刻只运行一个顾问；最多三轮只读查证及最终答复，默认 300 秒总截止（可用 DSH_PO06_ADVISOR_TIMEOUT_MS 调整，60 秒~15 分钟）；取消信号传至模型，无无限重试。插件关闭时工具返回明确拒绝。

## 顾问专用卡片
使用宿主 tool.call.toolview keyed 插槽（consult_task），同时覆盖根调用和 PTC 嵌套调用。不修改宿主或其它工具视图。真实 delta 接入独立进度缓存，GET /po06/api/advisor-progress 按 session + call/run 查询，沿用可信源检查。

布局固定四块：原 AI 询问内容、顾问思考内容、顾问答复内容、验收结果。询问与答复直接可读，思考与验收各自独立折叠、默认收起。思考展开后实时更新，向上滚动不会被强拉回底部；查证记录与原始 JSON 收进相应的二级折叠区。状态与耗时保留在克制的标题栏，去掉整卡折叠和常驻技术字段。内部状态译成人话，原始 JSON 只放在可折叠的未采纳原文里。provider 不提供思考时不虚构。缓存最多 80 次记录，单次思考留最后 24,000 字符，正文草稿留最后 8,000 字符；有截断标识。已完结记录持久化在 DSH_HOME，仅用于 UI 回放，不回灌给执行模型。视觉效果由用户手测。

## 按问题分阶段专项复核
新增scope+focus：general兼容、geometry、appearance、code、interaction、performance、delivery、custom。专项focus必填，每次一个对象与检查目标。geometry/appearance只附图像，排除显式代码材料及历史工具记录，禁源码查证；代码类仅发相关路径/证据编号所对应的记录，先筛再截预算。delivery只发同session同真人请求覆盖摘要，不从头泛扫或继承跨轮结论。

覆盖记录持久化有界80条，汇总最近20个不同scope+focus，保存询问、材料指纹、报告/检查点，不保存思考流。delivery requiredReviews精确列scope+focus，requiredScopes仅类别提示；缺少具体清单、未验证、失效、材料变更或源码写操作revisionMarker变化阻挡通过。局部通过只对focus有效，不等于整个类别或工程通过。

版本边界：只重读已附材料，源码事件仅检测宿主记录的write/edit等；旧截图无法单独证明新的源码版本，外部写入/任意shell变更可能不被事件标记覆盖。因此不是完整工程依赖失效图，也不保证捕获所有关键变化；工作AI仍需如实说明变更并重审。

卡片新增范围/对象、范围排除材料、交付覆盖/缺失具体项与版本提示。工作协议按风险阶段触发，已有图片复用、有疑点再追源码；小任务可一次general，不固定堆调用数。不强制改模型或自动拉起顾问。

确定性专项5项、覆盖9项、卡片30项及全量69份通过；真实识图缺陷发现率待用户手测，不能凭隔离测试承诺漏检已解决。

## 通用性防线
scope是检查维度而非行业；提示词、参数说明与协议都不得出现具体行业词汇，`advisor-generality.test.mjs` 用词表机械拦截（坦克/炮塔/履带/负重轮/轮系等），并断言示例覆盖界面、逻辑、布局等不同形态任务。几何专项改写成通用关系检查（形状与比例、朝向、相对位置、间隙贴合、重叠穿插、对称与重复实例），画面专项为取景构图、明暗色彩、清晰度噪点、遮挡可见性；两类都明确“替代预览可证明形体错误，不能证明真实成品观感”。focus示例用多领域中性案例，不用开发中的具体案例，避免把专项做成定向检查。测试夹具保留具体案例属正常做法，不进模型请求。
